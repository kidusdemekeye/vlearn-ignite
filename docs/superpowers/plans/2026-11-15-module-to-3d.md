# Module → 3D Video Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A student uploads a networking module (PDF/PPTX/DOCX/TXT) and V Learn turns it into a validated, narrated 3D video of lessons, concept cards and a built-in OSI scene.

**Architecture:** Pure logic (course contract, prompts, pipeline, text extraction) lives in DOM-free modules tested in Node. A new three.js `Stage3D` implements the same interface as the 2D `Stage`, plus `showCard()` and `showOsi()`. `app/course.js` runs outline → lessons one at a time through `app/ai.js`, and the player auto-advances through items.

**Tech Stack:** Vanilla JS modules, three.js 0.160.0 (cdnjs ES module), pdf.js 3.11.174 (cdnjs UMD), JSZip 3.10.1 (cdnjs UMD; npm devDependency for tests), Node test runner, Playwright (Python) for one browser pass.

**Spec:** `docs/superpowers/specs/2026-11-15-module-to-3d-design.md` (read its "Decisions after the builder check" section too).

## Global Constraints

- Files are read in the browser; only extracted text is sent to the AI.
- Outline text input truncated to 25,000 characters, headings/slide titles first. Outline: 1–12 items.
- Card: 2–5 points, each ≤ 90 chars; narration ≤ 400 chars; ≥ 1 citation (library id or module page/slide).
- Module citation ids: `module_p<N>` (PDF page / text section) or `module_s<N>` (slide), N within the extracted page/slide count.
- Every AI lesson passes `validateLesson`; failed lessons become a fixed fallback card (no extra AI call).
- Labels: lessons "AI-built · structure checked, not hand-verified"; cards "From your module · AI summary"; OSI "Built-in · reviewed"; golden lessons "Built-in · reviewed".
- All AI calls through `app/ai.js`. Text via `textContent` or canvas, never `innerHTML`.
- WebGL unavailable → 3D toggle disabled, 2D used.
- Course material from D2L is never committed.

## Review Focus

1. **Scanned PDF / no text** → message "This file has no readable text (it may be scanned images)." and nothing sent to AI. Test in Task 2.
2. **Outline cites a page that doesn't exist** (e.g. `module_p40` for a 12-page file) → outline repair, then reject. Test in Task 1.
3. **Next item still generating when the current one ends** → player waits with "Building next part…", no skip, no crash. Test in Task 4 (pipeline emits items in order).
4. **Student uploads a second file mid-generation** → first run cancelled, its late results ignored. Test in Task 4.
5. **Huge module** (200 pages) → truncated to 25,000 chars with slide titles kept; outline still ≤ 12 items. Test in Task 2 (`truncateModule`).

- Text markers: each part prefixed `[page N]` or `[slide N]` so the AI can cite.

### Task 4: Course pipeline

**Files:**
- Create: `app/course.js`
- Test: `tests/pipeline.test.mjs`

**Interfaces:**
- Consumes: Task 1 functions, `app/ai.js` ai signature `ai(messages, { modelTier, signal }) -> { text }`.
- Produces: `buildCourse(module, ai, { onOutline(course), onItem(index, item), signal, maxRepairs = 2 }) -> Promise<course>`.
