# V Learn — Independent Review

> Step 10 of the plan. Reviewer did not write the code. Scope: `docs/01-spec.md`, `docs/02-plan.md`, `AGENTS.md`, `app/*.js`, `app/index.html`, `tests/*.mjs`. `npm test`: 43/43 pass. Validator, layout and rendering maths were probed with throwaway scripts (not committed).

## Summary

The security design holds up. Every AI or user string reaches the DOM through `textContent`, there is no `innerHTML`/`eval` anywhere, and citation `href`s can only be one of 30 hard-coded `https://` URLs because citations must match the library exactly, so a `javascript:` URL is impossible. AI output only reaches `Stage.load` after `validateLesson` returns `ok`. I found **no Critical issues**. The real problems are elsewhere. (1) The validator checks the fields it knows about and ignores everything else. A `highlight` step that carries a stray `path` passes validation, then breaks follow-ups for that step and puts unvalidated text into the tutor prompt. (2) Some demo-visible rendering and state bugs: packet pills get clipped at the stage edge in the ARP golden lesson, long captions spill out of their boxes, and a second AI request can start while one is already running. (3) The firewall golden lesson's framing ("block an attacker but let visitors in") implies the firewall can tell the two apart. Its own animation shows the scanner's port-443 probe going through. (4) The UI and spec say "passed validation" in a way that suggests factual accuracy. Validation proves the structure is sound, not that the content is true. Follow-up answers are not validated or cited at all.

## What's good

- **The core XSS defence is real**, not just stated: one `make()`/`txt()` helper path, all `textContent`, attribute values are numbers or validated enums (`data-proto`), no `innerHTML` anywhere (checked with grep).
- **The citation allowlist is strict**: id, title and URL must all match exactly, so altered URLs and `javascript:` links are impossible, and links use `rel="noopener noreferrer"`.
- **Validation is strictly two-phase.** Semantic checks only run once the structure is sound, and the engine only ever sees `result.lesson` from an `ok` result. The repair loop is capped (3 calls total), sends back concrete error messages and refuses to show a "shaky" lesson.
- **No secrets**. AI runs through the viewer's own `sample` session. The `sample`/`tts`/`dictation` usage matches the runtime contract: `onText` assigns the whole text, `start()` is called directly from the click, every promise is caught, and a `null` capability degrades gracefully.
- **Player cancellation is mostly right**: the run counter plus the stage token correctly stop stale `runFrom` loops and rAF animations on pause, seek and lesson change, and the speech fallback has a guard timer for browsers that never fire `onend`.
- **The golden lessons are accurate on the core mechanics**: iterative DNS with referrals and TTL caching, the TCP 3-way handshake, the DHCP DORA sequence including why the Request is broadcast, and ARP broadcast request / unicast reply / opportunistic learning. Addresses are documentation or private ranges throughout (MAC uses a locally-administered `02:` prefix), and this is enforced by a test.
- Reduced motion is respected in both CSS and JS, and the dark theme is fully tokenised.
